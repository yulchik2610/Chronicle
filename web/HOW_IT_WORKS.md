# Chronicle — как устроен сайт и дапка

Odds-деривативы ончейн. Пользователь торгует не исходом события, а **движением вероятности**: покупает бинарный опцион ABOVE/BELOW на индекс вероятности, риск и выплата известны заранее, расчёт делает контракт.

---

## 1. Структура страницы (сверху вниз)

Всё живёт в одном файле `web/src/App.tsx`, компонент `App()`.

| Блок | class / id | Что делает |
|------|-----------|------------|
| Фон-фреска | `.hero-media` / `.hero-mural` | Картинка `HERO_MURAL` (`App.tsx:53`) из `web/public/assets/` |
| Шапка | `.site-header` | Логотип, навигация, кнопка кошелька |
| Hero | `.hero-strip` | Заголовок + центральная карточка `.hero-prompt` |
| Полоса статистики | `.stats-rail` id=`liquidity` | TVL пула, свободная ликвидность, сеть |
| Polymarket Pulse | `PolymarketPulse` | Живой источник тем с Polymarket |
| Как работает | `.explain-section` id=`markets` | 4 карточки механики + flow-цепочка |
| Торговля | `.trading-layout` | Список серий + тикет ставки |

## 2. Как делать ставку (шаг за шагом)

Панель ставки — `aside.trade-ticket` (`App.tsx:1047`).

1. **Выбрать серию.** Кликаешь карточку в `.market-grid` → `setSelected(series)`, сторона сбрасывается на ABOVE.
2. **Выбрать сторону** в `.side-toggle`:
   - **ABOVE** (`side=0`) — ждёшь, что индекс будет **выше** страйка.
   - **BELOW** (`side=1`) — ждёшь, что **ниже** страйка.
3. **Ввести количество контрактов** — поле `.amount-field` (только цифры), есть быстрые кнопки 10 / 25.
4. **Смотришь сводку** `.ticket-summary`: стоимость (премия), макс. выплата, потенциальная прибыль.
5. **Жмёшь `Купить ABOVE/BELOW`** → `handleTrade()`.

### Что делает `handleTrade()` (`App.tsx:752`)

```
1. ensureCorrectChain()             — проверка/переключение сети
2. если allowance < premium:
     approve(USDC → OptionContract) — стадия "approving"
     ждём receipt                   — стадия "confirming"
3. buy(seriesId, side, amount, premium)  — стадия "submitting"
4. ждём receipt                     — стадия "confirming" → "success"
5. refreshOnchain()                 — обновляем балансы/позиции
```

Стадии кнопки (`txStage`): `idle → approving → confirming → submitting → confirming → success`. При ошибке → назад в `idle` + текст в `.tx-message.error`.

### Кнопка меняет текст в зависимости от состояния

- нет кошелька → «Сначала подключите кошелёк»
- серия preview (контракты не задеплоены) → «Нужен деплой контрактов»
- неверная сеть → «Переключиться на {сеть}» (`ensureCorrectChain`)
- в процессе → спиннер + «Разрешение USDC… / Подтверждение… / Отправка ставки…»
- успех → «Позиция открыта»

### Фосет (тестовые деньги)

Если `faucetEnabled` и кошелёк подключён — кнопка `Получить 100 test mUSDC` → `handleFaucet()` → `mint(address, 100 USDC)`.

### Забрать выигрыш

`handleClaim(position)` (`App.tsx:821`) → `claim(seriesId, side, amount)`. После экспирации оракул закрывает результат, победившая сторона делает claim, проигравшая сгорает.

## 3. Механика контрактов (жизненный цикл серии)

```
LISTING → BUY ABOVE/BELOW → POOL RESERVE → ORACLE SETTLEMENT → CLAIM USDC
```

1. **Рынок как серия** — фабрика создаёт контракт с вопросом, страйком и датой экспирации.
2. **Трейдер выбирает сторону** — ABOVE / BELOW относительно страйка.
3. **Пул резервирует выплату** — `OptionPool` блокирует номинал под возможную выплату, поэтому макс. риск и макс. выплата видны до входа.
4. **Оракул закрывает результат** — `OddsIndexOracle` передаёт финальный индекс после экспирации.

Контракты, задействованные во фронте (`contracts` в конфиге):
- `contracts.usdc` — ERC-20 USDC (`approve`, `mint`)
- `contracts.option` — бинарный опцион (`buy`, `claim`)
- `OptionPool` — резерв обеспечения
- `OddsIndexOracle` — расчёт по TWAP

Гарантии (блок `.trust-ledger`):
- **USDC collateral** — пул резервирует макс. выплату в момент покупки.
- **TWAP settlement** — цена экспирации из append-only odds oracle.
- **ERC-1155 position** — позиция принадлежит кошельку, передаваема.

## 4. Дизайн и стили

Всё в `web/src/styles.css`. Тема: тёплая «бумажная» фреска-коллаж.

### Палитра (CSS-переменные, `:root`)
- `--paper` — фон бумаги
- `--ink` — основной тёмный текст/кнопки
- `--terracotta` — акцент (кикеры, индексы, hover)
- `--green` — позитивные значения/прибыль

### Типографика (`@fontsource`)
- `--display` — Cormorant Garamond (заголовки)
- Manrope — основной текст
- IBM Plex Mono — цифры/метки

### Ключевые компоненты стилей
- `.hero-prompt` — центральная стеклянная карточка (`backdrop-filter: blur`), уже уменьшена: `width: min(540px,100%)`, `min-height: 108px`.
- `.prompt-signal` — круглая кнопка-иконка 38×38 с анимацией кольца.
- `.primary-action` — главная кнопка ставки (тёмная, `--ink`, hover-подъём).
- `.side-toggle` — переключатель ABOVE/BELOW.
- Анимации в `@media (prefers-reduced-motion: no-preference)`: `prompt-in`, `prompt-float`, `glass-sheen`, `stamp-drift`.
- Адаптив: брейкпоинты внизу файла (`.hero-prompt`, `.trading-layout` перестраиваются на мобилке).

## 5. Навигация и известные проблемы

### Верхняя навигация (`.site-header nav`, `App.tsx:861`)
Работает через якоря:
- `Как работает` → `#markets`
- `Ликвидность` → `#liquidity`

### ⚠️ Футер не кликабельный (`App.tsx:1212`)
Сейчас в футере **нет рабочих ссылок**:
```jsx
<footer>
  <ChronicleMark />                        // ведёт на "#" (наверх, но по сути никуда)
  <span>ODDS DERIVATIVES PROTOCOL / 2026</span>   // просто текст
  <span>TESTNET-READY · NOT AUDITED</span>        // просто текст
</footer>
```
Поэтому «снизу сайта ничего не работает / переход не бачит» — это ожидаемо, ссылок там не заложено.

**Чтобы починить** — заменить `<span>` на `<a href="#...">` с якорями на существующие секции, например:

```jsx
<footer>
  <ChronicleMark />
  <nav className="footer-nav" aria-label="Футер">
    <a href="#markets">Как работает</a>
    <a href="#markets">Рынки</a>
    <a href="#liquidity">Ликвидность</a>
  </nav>
  <span>ODDS DERIVATIVES PROTOCOL / 2026</span>
  <span>TESTNET-READY · NOT AUDITED</span>
</footer>
```

Якоря, которые уже есть на странице: `#markets` (секция «Как работает» + торговля), `#liquidity` (полоса статистики). Логотип `ChronicleMark` ведёт на `#` — при желании можно поменять на плавный скролл наверх.

### Кнопка ставки «не работает»
Кнопка `.primary-action` **намеренно заблокирована** (`disabled`), пока не выполнены условия:
- кошелёк не подключён,
- контракты не сконфигурированы (`contractsConfigured`),
- серия в режиме `preview` (нужен деплой),
- количество ≤ 0,
- транзакция уже идёт.

То есть без задеплоенных контрактов и подключённого кошелька ставку сделать нельзя — это не баг, а защита. Для локальной проверки нужен деплой контрактов (`pnpm deploy:local`) и адреса в `.env` фронта.

## 6. Как запустить локально

```bash
# из корня репо
cd web
npx vite            # dev-сервер на http://127.0.0.1:4173/
```

Для реальных ставок дополнительно:
```bash
# из корня
npm run node          # локальная сеть hardhat
npm run deploy:local  # деплой контрактов
# затем адреса контрактов прописать в web/.env
```
